## 2. 기업이 명시한 문제와 필수 검증

기업 PDF는 다음 두 문제를 직접 제시한다. 기업의 내부 상황을 추가로 추측해서 공식 요구사항처럼 표현하지 않는다.

1. AI 추론시간은 가변적이지만 로봇 제어는 일정한 주기가 필요하다. 직접 결합하면 제어 지연·지터가 발생할 수 있다. 용융풀 상태 기반 용접 적응제어에도 이 제약이 작용한다.
2. 제조사·기종별 제어 인터페이스가 달라 AI 작업 애플리케이션을 이식할 때 재개발이 필요하다. 상위 AI와 하위 제어기를 분리하고 HAL이 차이를 흡수해야 한다.

| 요구 | 구현·측정으로 제시할 증거 |
|---|---|
| AI / 실시간 제어 / 통신·HAL 분리 | 아키텍처, 인터페이스, 태스크 우선순위, CPU·IPC 자원 분리 |
| 기본 목표 제어주기 1ms(1kHz), 목표 지터 ±100μs | B 루프의 실제 wall-clock 주기·지터 분포와 최댓값, 기준과 시험 조건 |
| AI가 동시에 수행될 때 제어 주기 유지 | AI 없음/있음/고부하 조건의 같은 방법에 의한 비교 |
| 추론값 반영 시점·유효기간 관리 | 프레임·추론·B 반영·C 처리·장치 적용을 식별자로 연결한 로그 |
| 지연·누락·이상값·단절 대응 | 값·범위·시간 검사, 기존 제어값 유지 또는 합의한 정지, 복구 시 목표 급변 검사 |
| 제조사 비종속 HAL | 동일 상위 TCP 명령·상태·오류 구조, 로봇별 모델·설정·어댑터 분리 |
| 성능 시각화 | 주기·지터, AI 추론시간·추론주기, E2E 지연, 조건별 동작 비교 |

실 로봇 또는 시뮬레이터, 간소화된 제어 대상을 허용하며 후보 시연 중 하나 이상을 구현하도록 한다. 팀은 요약서에서 1·3·4를 선택했으므로, 기업의 최소 범위와 팀이 제안한 범위를 구분한다. PDF는 EtherCAT·ROS 2 등 통신·기종 차이를 흡수하는 구조를 요구하고, 착안점 이미지는 표준 인터페이스 연동·안전기능을 평가한다. ROS 2 실연동, 보호 기능 증거, EtherCAT의 구현 또는 확장 설계 범위를 각각 명시하며 미구현 기능을 구현했다고 표현하지 않는다.

## 3. 제출 요약서의 약속

- 제목: **AI는 늦어도 제어는 멈추지 않는 상위제어 플랫폼**. 여기서 제어 지속은 B 주기 유지이며, 모든 장애에서 로봇의 운동을 계속 허용한다는 뜻으로 사용하지 않는다.
- 최신값을 읽는 비차단 연결, AI를 기다리지 않는 1ms B 루프, 유효성·신뢰도·신선도 반영과 속도·가속도 제한.
- B는 공통 작업 좌표의 절대 TCP pose를 만들고 C는 형식·시간 검사, 좌표 변환, IK/FK, 관절·장치 변환, 전송, 상태·오류를 담당한다.
- 원안은 HA006B가 토치, HDR50-22가 작업물 배치·고정·반출, UR5e가 교체 토치 역할이다. 현재 사용자가 정한 FR3 집중 및 이후 UR5e는 원안 대비 변경 사항이다. 현대 로봇·협업 시연을 완료했다고 주장하지 않는다.
- 시나리오 1: 대상물 이동, 추론 지연·중단·이상값 주입, 부드러운 목표 보정.
- 시나리오 3: 실제 기준선 대비 편차 보정, 용접선 검출 실패·지연 시 마지막 보정 유지. 실제 용접 품질 개선 검증과 구분한다.
- 시나리오 4: 두 토치 로봇의 공통 실행 가능 경로, A·B 코드와 상위 작업 로직 유지, 로봇별 C 설정·어댑터 교체. IK 실패·상태 수신 중단·과거 명령 재전달을 주입한다.
- 협업 원안에서는 경로 완료뿐 아니라 토치 이탈 확인 후 작업물을 해제·반출하며, 로봇 오류 때 작업 진행·반출을 보류한다. FR3→UR5e 단일 로봇 교체 시험은 이 협업 전체를 검증한 것이 아니다.
- B 주기·지터와 C/로봇의 전달·적용 주기는 별도로 측정한다. ACK는 명령과 대응하는 수신·적용 확인이며 일반 상태 수신을 처리 완료로 간주하지 않는다.
- 시나리오 4의 요약서 예시 기준은 TCP 오차 1mm 이내 100ms 유지 및 상위 코드 변경 0줄이다. 현재 도착 판정 2mm/0.3초와는 다르므로 시험 전 기준을 고정하고 각 결과를 따로 보고한다.

## 4. 현재 구현과 제안의 차이·미검증 범위

시나리오 4 업데이트: FR3·UR5e 공통 C++ HAL과 로봇별 작업셀을 구현했고, 가짜 A→실제 B→C→Gazebo의 기본 이동·HOLD·FAULT·watchdog·순번 유지 시험은 두 로봇에서 통과했다. 자세한 현재 결과와 추가 경로 시험의 조건·한계는 [공통 HAL 보고서](scenario4-common-hal-2026-10-07.md)를 따른다.

| 항목 | 제출 원안 | 현재 기준/상태 | 필요한 조치 |
|---|---|---|---|
| IPC | A–B, B–C Seqlock 공유메모리 | 팀 실제 연결은 ROS 2 토픽 계약 | 비차단 최신값 처리·지연·지터 실측으로 선택 근거 설명. 원안 구현으로 표기 금지 |
| 배치 | 제어기 PC에서 A/B/C, 별도 로봇 PC | B/C 같은 PC, A는 다른 PC도 허용 | 같은 PC의 AI 부하 시험 또는 동등한 경쟁 부하 시험을 구분해 설계. 원격 A만으로 동일 자원 경쟁을 검증했다고 하지 않음 |
| 실시간 OS | PREEMPT_RT, 격리 코어, FIFO 등 | 이전 검증 일반 PREEMPT_DYNAMIC, FIFO 미검증 | 실제 환경 기록, RT 구성·부하 비교. 1kHz±100μs 달성은 미검증 |
| AI 시간 | 50~150ms, 약 7~20Hz 예상 | 모델/장비별 실측 필요 | 예상치를 측정값으로 사용하지 않음 |
| 유효기간 | AI 200ms 제안 | 현재 계약/설정 확인 필요. B→C TTL 5ms | AI TTL과 B→C TTL을 구분하고 최종 팀 설정 기록 |
| 로봇 | HA006B/HDR50-22/UR5e | FR3·UR5e 기본 교체 실행 검증, 긴 경로/실물/협업 남음 | 변경 이유·범위 기록, 공통 HAL 및 협업을 별도 단계로 검증 |
| 센서 | 손목 RGB-D 카메라 | 현재 상부/외부 카메라 제안 | 실제 카메라 설치·TF 기준 명시, 영상 기반 A E2E 시험 |
| C 안전 기능 | 공통 오류·상태·제약 검사 | FR3·UR5e 공통 C++ 검사·장면·상태/오류·watchdog | 6·7축 공통화 완료, 로봇별 조건·장애 검증 지속 |
| 최신 FR3 증거 | 전체 A→B→C 실증 목표 | 가짜 A→실제 B 및 B 수정 제안 사본→C 시험 포함 | 가짜 A, 제안 B, 제안 월드, 실제 팀 코드 결과를 분리해 보고 |

현재 수치·검증 범위는 `fr3-delay-recovery-2026-10-07.md` 등 개별 보고서를 따른다. 특정 조건에서 작은 위치 오차 또는 짧은 C 처리시간을 얻었다고 B 주기·지터, 실제 A 연결, 실물 안전 또는 용접 품질이 검증된 것으로 확대하지 않는다.

## 5. 본선 평가표와 작업 우선순위

5개 지표 각 20점, 총 100점. 공지에 기재된 동점 처리 우선순위는 **현장 적용 가능성 → 기술 성숙도 → 기업 도입 의향**이다.

| 지표 | 공지의 판단 요소 | 우리 결과물에 포함할 증거 |
|---|---|---|
| 문제의 정합성 | 출제기업 요구 충족, 문제 정의→해결의 일관성, IR 설득력 | 기업 문제→A/B/C 설계→정상·장애 시연→실측 결과 연결 |
| 기술 성숙도 | AI 정확도·처리속도·효율 검증, 제어 구현·안정성 | 실제 A 검출 성능, B 주기·지터, HAL/장치 지연, 오류 복구 재현 |
| 현장 적용 가능성 | 핵심 역할, 작업자 유용성, 실제 공정 제약 대응 | 좌표/TCP·간섭·도달성·통신 장애 대응, 운영·복구 절차, 실증 한계 |
| 사업화·실증 연계 및 성장 가능성 | 사업화·IP·투자·매출·후속 공동개발 실행력 | 기존 기술과 차이, 후속 용융풀 제어/이종 HAL 계획, 개발·검증 단계 |
| 기업 도입 의향 | 도입 비용 대비 절감액·회수기간의 근거, 도입·확산 타당성 | 로봇 추가 시 변경 파일·개발/검증 시간·재사용률, 비용 산정 가정 및 검증 계획 |

과제 4 전용 착안점은 **제어주기 준수·지연·지터의 실시간성**, **AI 추론과 실시간 제어의 자원 분리·연동**, **EtherCAT·ROS 2 등 표준 인터페이스 연동 및 안전기능**이다. 원가·절감액·회수기간과 기업 도입 의향은 근거가 없으면 추정/미확인으로 표시하고 수치를 만들지 않는다.

작업은 (1) A/B/C 실제 연계와 장애 대응, (2) 실시간 환경 및 부하별 정량 검증, (3) FR3/UR5e 공통 HAL, (4) 협업·공정 확장과 도입 근거 순으로 진행하되 사용자 우선순위를 따른다. 단순 C IK 속도 최적화가 전체 과제 실시간성을 대체하지 않는다.

## 6. 매 작업의 확인 사항

1. 어떤 기업 요구·팀 약속·평가 항목을 해결하는지 적는다.
2. 공통 계약과 계층 책임을 유지하고 변경이 필요하면 이유를 기록한다.
3. 시험 전에 조건·측정 위치·시계·합격 기준을 정한다. 시뮬 시간과 wall-clock, CPU 처리시간과 wall 지연을 구분한다.
4. 정상 및 관련 장애·복구를 검증하며, C 오류 때 작업 진행 통제와 수신단 watchdog을 함께 확인한다.
5. 원본 로그·명령 식별자·재현 명령을 남기고 달성/미달/미검증을 구분한다.
6. 제출 원안 대비 변경, 가짜 구성요소, 미구현 범위 및 후속 계획을 보고한다.
7. 추가 push·PR·병합은 사용자 검토와 승인 후 진행한다.
